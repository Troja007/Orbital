# Windows Browser Extension Domain Investigation

These are read-only Orbital/osquery drafts for investigating a domain that may
be generated by a browser extension. They are scoped to `x.bidswitch.net` and
the related `bidswitch.net` suffix. Run each query independently so an empty
result is attributable to one evidence area.

Recommended order:

1. DNS cache, hosts-file, and DNS Client event-log checks establish current or
   retained domain evidence.
2. Chromium content-script and manifest checks look for a direct extension
   reference to the domain.
3. Chromium and Firefox metadata checks look for direct references; inventories identify installed extensions even when
   they do not embed the domain in their exposed metadata.
4. Browser, proxy, and extension-policy checks look for direct references and
   identify force-installed extensions. Native-messaging checks identify
   locally integrated extensions.
5. Startup items, scheduled tasks, and services search persistence or
   automation configuration for the literal domain.
6. Process command-line, Sysmon, Security, and Cisco Secure Endpoint channel
   checks search retained endpoint telemetry for the literal domain.
7. Broad-host Chromium and legacy IE extension inventories identify extension
   candidates for correlation when no direct domain reference is exposed.
8. Browser process sockets provide current IP-layer context only. Correlate
   remote IPs to `x.bidswitch.net` with proxy, DNS resolver, or network
   telemetry; sockets do not carry DNS names.

Notes:

- `chrome_extensions` includes Chrome, Edge, Brave, Chromium, Opera, Yandex,
  and related Chromium-based profiles when Orbital supports the table.
- `chrome_extension_content_scripts` reports manifest-declared match patterns,
  not browser navigation history.
- `firefox_addons` exposes addon metadata and source URLs but not every XPI
  manifest field.
- The local osquery 5.23.0 schema used by this project does not provide a
  browser-history table or a general-purpose file-content search. These drafts
  therefore cover supported endpoint surfaces, not every possible historical
  browser artifact. Use proxy, DNS resolver, EDR, or browser-forensic exports
  for those gaps.
- An empty query result means no matching data was exposed by that table at
  execution time. It does not prove the endpoint never contacted the domain or
  that no extension was involved.
- Validate table availability on one narrow Windows host before a broader
  target set. Do not combine these queries into one large `UNION` query.

## Reputation And Interpretation

BidSwitch documents `https://x.bidswitch.net/sync` as its HTTPS browser
user-matching endpoint. Its normal advertising workflow redirects browsers to
that endpoint to synchronize identifiers, so high browser DNS or web-request
volume alone is not evidence of malware or a malicious extension. See the
[BidSwitch user-matching documentation](https://protocol.bidswitch.com/features/user-matching.html)
and the [Netify hostname profile](https://www.netify.ai/resources/hostnames/x.bidswitch.net).

Historical sandbox and consumer-removal references place the hostname in
advertising-redirect or malvertising investigations. They are not a reliable
current verdict on the domain itself: for example, the
[2019 ANY.RUN report](https://any.run/report/de6a427795cf3d2f9ea16dd499188bf89fd5b23831f46621a2dba1e48dc6c5c8/ab633cbb-8c81-471e-b941-aeb8307c666d)
contains a generic page label but reports no malicious or suspicious indicators
in its own behavior summary. Treat the hostname as ad-tech infrastructure that
requires endpoint investigation only when it is tied to an unexpected process,
forced extension or policy, persistence mechanism, suspicious redirect chain,
or anomalous network behavior.

### DNS Cache

[Source SQL](draft_windows_dns_cache_bidswitch.sql)

```sql
SELECT
  name AS domain,
  type AS record_type,
  flags
FROM dns_cache
WHERE lower(name) = 'x.bidswitch.net'
   OR lower(name) LIKE '%.bidswitch.net'
ORDER BY domain, record_type;
```

### Hosts File

[Source SQL](draft_windows_hosts_file_bidswitch.sql)

```sql
SELECT
  address,
  hostnames
FROM etc_hosts
WHERE lower(hostnames) = 'x.bidswitch.net'
   OR lower(hostnames) LIKE '%.bidswitch.net'
ORDER BY hostnames, address;
```

### DNS Client Events

[Source SQL](draft_windows_dns_client_events_bidswitch.sql)

```sql
SELECT
  datetime,
  provider_name,
  eventid,
  level,
  data
FROM windows_eventlog
WHERE channel = 'Microsoft-Windows-DNS-Client/Operational'
  AND lower(data) LIKE '%bidswitch.net%'
ORDER BY datetime DESC
LIMIT 200;
```

### Sysmon Events

[Source SQL](draft_windows_sysmon_bidswitch.sql)

```sql
SELECT

  data
FROM windows_eventlog
WHERE channel = 'Microsoft-Windows-Sysmon/Operational'
  AND eventid IN (1, 3, 22)

LIMIT 200;
```

### Chromium Content Scripts

[Source SQL](draft_windows_chromium_content_script_bidswitch.sql)

```sql
SELECT
  browser_type, uid, identifier, version, script, match,
  referenced, profile_path, path
FROM chrome_extension_content_scripts
WHERE lower(match) LIKE '%bidswitch.net%'
   OR lower(script) LIKE '%bidswitch%'
ORDER BY browser_type, uid, identifier, version, script;
```

### Chromium Manifest And Permissions

[Source SQL](draft_windows_chromium_extension_manifest_bidswitch.sql)

```sql
SELECT
  browser_type, uid, profile, name, identifier, version, referenced, state,
  from_webstore, update_url, permissions_json, optional_permissions_json,
  manifest_hash, path
FROM chrome_extensions
WHERE lower(manifest_json) LIKE '%bidswitch.net%'
   OR lower(permissions_json) LIKE '%bidswitch.net%'
   OR lower(optional_permissions_json) LIKE '%bidswitch.net%'
   OR lower(update_url) LIKE '%bidswitch.net%'
   OR lower(description) LIKE '%bidswitch%'

```

## Supporting Correlation Queries

These commands do not necessarily contain the domain. Use them to identify an
extension ID, user, browser policy, local integration, or IP connection that
can be correlated with a direct literal-domain hit.

### Chromium Extension Inventory

[Source SQL](draft_windows_chromium_extension_inventory.sql)

```sql
SELECT
  ce.browser_type, ce.uid, COALESCE(u.username, '') AS username, ce.profile,
  ce.name, ce.identifier, ce.referenced_identifier, ce.version, ce.description,
  ce.referenced, ce.state, ce.from_webstore, ce.update_url,
  ce.install_timestamp, ce.manifest_hash, ce.path
FROM chrome_extensions ce
LEFT JOIN users u ON u.uid = ce.uid
ORDER BY ce.browser_type, ce.uid, ce.profile, ce.name, ce.identifier, ce.version;
```

### Chromium Extensions With Broad Host Access

[Source SQL](draft_windows_chromium_extensions_broad_host_access.sql)

```sql
SELECT
  browser_type,
  uid,
  profile,
  name,
  identifier,
  version,
  referenced,
  state,
  permissions_json,
  optional_permissions_json,
  manifest_hash,
  path
FROM chrome_extensions
WHERE state = '1'
  AND (
    lower(permissions_json) LIKE '%<all_urls>%'
    OR lower(optional_permissions_json) LIKE '%<all_urls>%'
    OR lower(manifest_json) LIKE '%://*%'
  )
ORDER BY browser_type, uid, profile, name, identifier, version;
```

### Microsoft Edge Current Connections

[Source SQL](draft_windows_msedge_process_sockets.sql)

```sql
SELECT
  p.pid,
  p.name,
  p.path,
  p.cmdline,
  datetime(p.start_time, 'unixepoch', 'UTC') AS process_start_utc,
  pos.protocol,
  pos.local_address,
  pos.local_port,
  pos.remote_address,
  pos.remote_port,
  pos.state
FROM process_open_sockets pos
JOIN processes p ON p.pid = pos.pid
WHERE lower(p.name) = 'msedge.exe'
  AND pos.remote_address NOT IN ('', '0.0.0.0', '127.0.0.1', '::', '::1')
ORDER BY p.pid, pos.remote_address, pos.remote_port;
```

### Current Browser Sockets

[Source SQL](draft_windows_browser_process_sockets.sql)

```sql
SELECT
  p.pid, p.name AS process_name, p.path AS process_path, p.cmdline,
  datetime(p.start_time, 'unixepoch', 'UTC') AS process_start_utc,
  pos.protocol, pos.local_address, pos.local_port,
  pos.remote_address, pos.remote_port, pos.state
FROM process_open_sockets pos
JOIN processes p ON p.pid = pos.pid
WHERE lower(p.name) IN ('chrome.exe', 'msedge.exe', 'brave.exe', 'opera.exe', 'firefox.exe')
  AND pos.remote_address NOT IN ('', '0.0.0.0', '127.0.0.1', '::', '::1')
ORDER BY p.name, p.pid, pos.remote_address, pos.remote_port;
```
